# ADR-0078: Developer ID signed engine release for Xode

Status: Accepted (owner directive, REQ-115)
Date: 2026-10-25

## Context

ADR-0002 chose ad-hoc signing only, because the maintainer could not pay
for an Apple Developer ID. That reason no longer holds: the maintainer
now has the identity "Developer ID Application: Dragos Hont (M62Z4M5EUY)".

ADR-0020 archived the engine and turned this repository into a recipe.
Since then the runtime-adapter lane (ADR numbers 0021 to 0077, kept on
an unpublished branch) built Wine 11.20 from source again, isolated
from the old Phase 1 to 5 plan, to serve Xode (the macOS front-end that
was called "Ode to X"). Xode now uses one admitted engine for its
games: WineHQ 11.20 with the D3DMetal integration ported from
CodeWeavers' LGPL source, a source-built TLS stack, source-built
MoltenVK 1.4.2 and Apple's D3DMetal 4.0 beta 3. Its registry is
called 170ca after its hash.

That engine only exists inside a developer checkout. Xode cannot find
it on any other Mac. The owner asked (REQ-115, COR-185, COR-186) to
"pack it, build it, sign it" with the Developer ID so that beta users
download one engine and Xode detects it.

ADR numbers 0021 to 0077 are used by the unpublished lane. This ADR
takes the next free number so the two histories can be merged later
without renumbering.

## Decision

1. **Version.** The engine version is `<Wine>-<Apple D3DMetal>-<our patch
   counter>`. The first release is `11.20-4.0b3-01`: Wine version from
   the source tree's `VERSION` file ("Wine version 11.20") and the
   D3DMetal version from the framework's `Info.plist`
   (`CFBundleShortVersionString` = `4.0b3`). The counter is ours and
   resets when either upstream version changes. Xode's own product
   version (0.11.4 beta) is separate.
2. **Build from committed source.** `tools/release_engine.py build`
   extracts the official `wine-11.20.tar.xz` (sha256-pinned; the same
   file tree as the `wine-11.20` git tag) and applies the patch series
   in `patches/wine-11.20/`. Patch 0001 is the admitted 170ca source
   delta (generated by `tools/port_d3dmetal.py` from CodeWeavers'
   CrossOver 26.3.0 LGPL source). Patches 0002 to 0005 are generic Wine
   fixes from the paused Forza Horizon 6 research. FreeType and the
   GnuTLS stack are rebuilt from pinned tarballs with
   `tools/build_freetype.py` and `tools/build_tls.py`. MoltenVK is the
   pinned `tools/build_moltenvk.py --metal-private-api` build that 170ca
   already uses (sha256 checked).
3. **Relocatable layout.** Wine is configured with an `@rpath` SONAME for
   FreeType, GnuTLS and MoltenVK, and every Unix module gets the rpath
   `@loader_path/`. Bundled dylibs sit next to the Wine Unix modules and
   find each other through `@loader_path`. No load command may contain
   `/Users`, `/opt/homebrew`, `/usr/local` or `/tmp`.
   `DYLD_FALLBACK_LIBRARY_PATH` is no longer needed.
4. **Signing.** Every Calimocho Mach-O is signed inside-out (libraries
   first, then executables), one file at a time, with
   `codesign --force --sign <identity> --options runtime --timestamp`.
   There is no `--deep`. Executables also get
   `scripts/wine-entitlements.plist` (JIT, unsigned executable memory,
   no executable page protection, DYLD environment variables, no library
   validation). Wine needs these to map Windows code.
5. **Apple components keep Apple's signature.** `D3DMetal.framework` and
   `libd3dshared.dylib` are copied unmodified from the owner's own copy
   of Apple's "Evaluation environment for Windows games 4.0 beta 3". Every
   file is checked against `versions.json`. The GPTK licence (section 2D)
   forbids modifying the Apple Software, and re-signing rewrites the
   binary, so we do not re-sign them. Scripts never download Apple files,
   and Apple files are never committed.
6. **No notarization yet.** The archive is notarization-ready (a zip
   holding hardened-runtime, timestamped, Developer ID code), but we do
   not submit it. Notarization and publication are separate owner
   decisions.
7. **Install location.** `~/Library/Application Support/Xode/Engines/<engine-id>/`
   with a `calimocho-engine.json` manifest at its root. Paths in the
   manifest are relative. Xode downloads and installs the engine there,
   or the user extracts the zip there.
8. **Corresponding source.** Every binary archive is produced next to a
   `<engine-id>-source.tar`. It holds the Wine tarball, the patches, the
   build scripts and the LGPL dependency tarballs. `SOURCE.md` inside the
   engine adds a written offer (ADR-0012 still applies).

## Consequences

- This supersedes ADR-0002 for release artifacts. ADR-0002 is deleted,
  as AGENTS.md asks for superseded ADRs. AGENTS.md rule 8 now describes
  Developer ID signing.
- Users still see a Gatekeeper warning until the archive is notarized.
  Downloading through Xode (no quarantine attribute) avoids it.
- The archive bundles Apple software. Apple's licence allows
  distribution only for non-commercial purposes and asks us to keep
  Apple's notices (sections 2A(iii) and 2C). Whether Xode or Working
  Principle may bundle it depends on whether that distribution is
  non-commercial. That is an owner decision; this ADR does not affirm
  it.
- Game-specific Forza Horizon 6 changes (CodeWeavers W^X and MXCSR
  hacks, the GPU identity spoof, and a d3d12 shim taken from an
  external engine whose licence we have not reviewed) are not in the
  engine. Forza needs them, so Forza stays on its research engine
  until the owner decides on a per-game, opt-in route.
- Other games may only claim support on this engine after a launch
  sweep on the release build itself.
