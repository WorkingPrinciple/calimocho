# Forza Horizon 6 stutter on Calimocho (REQ-129), 2026-10-26

Status: research and measurement plan. No engine fix is claimed.
Reopened by the owner (COR-267). The analysis stays inside COR-266:
read-only analysis to make a legally owned game run, no DRM removal,
no patching of the game, nothing redistributed.

## Short answer

The best-supported cause of the regular FH6 hitch on Apple Silicon is
outside Wine. It is how expensive Rosetta 2 makes a trapped x86
instruction. FH6's copy protection runs a job about every 1.1 s. The job
executes about 2,000 instructions that trap on purpose, and the game's
own exception handler emulates each one while holding a lock the frame
needs. On a PC that job takes a few milliseconds. Under Rosetta each
trap costs about 57 µs in the game, so the frame stalls for 100 to
130 ms about once a second. Highball measured this and filed Apple
Feedback FB25100017 on 2026-10-09. Wine's own share is about 5 %.

Calimocho can't remove the hitch without either Apple changing Rosetta
or someone changing the game's protection code. Changing the protection
code is out of scope (COR-266, AGENTS rule 4). What we can do is make
sure Calimocho adds nothing on top, and measure.

## Our own measurements (no game)

Apple M5 Max (as reported by MoltenVK), macOS 27, the Highball benchmarks built from
source in `/tmp`, idle except another session's build:

| Test | Result |
| --- | --- |
| `ud2` caught by a SIGILL handler, x86_64 under Rosetta | 15.47 µs |
| Same with 4 busy threads | 18.17 µs |
| `int3` caught by SIGTRAP under Rosetta | 16.63 µs |
| Native arm64 `udf` caught by SIGILL | 2.29 µs |
| Write into the 4 KB page of code that already ran, then call it | 13.2 to 13.6 µs |
| Same write into another 4 KB page | 0.00 µs |

These match Highball's M4 and M1 Pro numbers. Rosetta adds roughly a
factor of seven per trap on this Mac too.

## What Calimocho adds in this path

Static reading of our FH6 opt-ins (`patches/wine-11.20`, ADR-0079):

- 0006 (CW hacks 24945/25719) only acts on a write or execute fault on
  a page that is already writable+executable or executable. Then it
  calls `mprotect` twice on one host page. The `FIXME` lines in that
  path don't print, because the FH6 registry sets `WINEDEBUG=-all`.
  CrossOver 26.3 and Highball carry the same hack, so it is not a
  difference from them.
- 0007 (live MXCSR) reads one register in the signal context. That is
  negligible.
- 0009 (permanent NX under Rosetta) reduces Rosetta work. It stops
  ordinary mappings from becoming executable.
- Nothing in our tree changes Wine's SIGILL/SIGTRAP dispatch or
  `NtContinue`.

So we expect Calimocho's per-trap cost to match Highball's Wine 11
(CrossOver 26.3 sources). The table above is the floor without Wine.
`tests/fh6_stutter/trapbench.c` measures the cost with Wine and gives
the share Wine adds on our engine.

## Candidate fixes considered

| Candidate | Expected effect | Decision |
| --- | --- | --- |
| Raise the priority of the trapping thread and Rosetta's exception server | Highball measured about 18 % shorter stalls, even at real-time priority | Not taken: a small gain, and it pushes the Mac harder (COR-259) |
| Emulate the trapped instructions before they trap (patch the game) | Would remove the hitch | Out of scope: it modifies copy protection (COR-266, rule 4) |
| Keep the handler's writes off code pages | Would save about 13 µs per trap | Not possible from Wine: the game decides where it writes |
| Make Wine's exception dispatch cheaper | At most about 5 % of the stall | Measure first with `trapbench`; only worth it if our share is clearly above Highball's |
| Ask Apple (FB25100017) | The real fix | Recommended to the owner: file a duplicate that names FB25100017 |

## Measurement plan

The acceptance asks for a frame-time trace from a real free-roam drive
that shows no recurring hitches compared with the baseline. Without an
Apple fix, we expect that to **fail**. The plan below makes the failure
measurable and shows whether any Calimocho change helps.

1. **Mechanism check on the Xbox build (agent, title screen, about
   3 min).** While FH6 sits on the title screen, `sample <pid> 5`.
   Count samples in the `com.apple.rosetta.exceptionserver` thread and
   in the game's exception handler. A share well above zero, recurring
   in each second, confirms the same mechanism on our Xbox build.
2. **Wine's share (agent, no game, under 1 min).** Run
   `trapbench.exe 20000` and `trapbench.exe 20000 4` under the FH6
   engine in the same clone. Compare with the table above. Wine's share
   is `trapbench − sigbench`.
3. **Frame time (owner, free roam, 2 × 3 min).** Same save, controller
   and spot. Enable the Metal HUD with logging for this process only
   (`MTL_HUD_ENABLED=1 MTL_HUD_LOG_ENABLED=1`, read back with
   `log show --predicate 'eventMessage CONTAINS "metal-HUD"'`).
   Record frame-time maximums per second. Report the share of seconds
   with a frame over 50 ms and whether those seconds are about 1.1 s
   apart. Run once on -06 (baseline) and once on any candidate. The CLI
   pins the title environment, so the HUD variables need a recipe change
   from the Ode lane, or `launchctl setenv` for the run, reverted
   afterwards.

## Status

- Root cause: external (Rosetta trap cost), from public evidence and
  our matching measurements. Not yet confirmed on the Xbox build (step 1).
- Engine candidate: none that removes the hitch. trapbench is ready to
  show whether Calimocho adds cost above Highball.
- REQ-129 acceptance ("no recurring hitches") is not reachable until
  Apple changes Rosetta, unless step 2 finds a large Wine-side share.
