# Calimocho engine 0.1120.4.7 (calimocho-11.20-4.0b3-07): release notes draft

> If you can afford it, buy [CrossOver](https://www.codeweavers.com/crossover).
> CodeWeavers wrote most of the macOS Wine work this engine is built on,
> and CrossOver comes with support, which this engine does not.

**Status (2026-10-27): built and signed locally, not notarized, not
published.** Seventh Calimocho engine build. It adds the Xbox One S
Bluetooth LE controller fix on top of
[0.1120.4.6](11.20-4.0b3-06.md), which stays the current public
prerelease.

**Hold:** this build used Apple's Game Porting Toolkit files taken from
the installed 0.1120.4.6 engine instead of the owner's own copy of
Apple's "Evaluation environment for Windows games 4.0 beta 3". All 18
files match the SHA-256 pins in `versions.json` and keep Apple's
signatures, but this deviates from
[ADR-0078](../ADR/0078-developer-id-signed-engine-release.md). It must
not be notarized or published until the owner supplies or confirms the
GPTK source, and a rebuild from that source is the clean route.

## Version

Version **`0.1120.4.7`**: Wine 11.20, Apple Game Porting Toolkit 4
(D3DMetal `4.0b3`), Calimocho build 7. Engine ID
`calimocho-11.20-4.0b3-07`. Planned tag: `engine-0.1120.4.7`. Source:
<https://github.com/WorkingPrinciple/calimocho>.

## Graphics APIs

| API | Path in this engine |
| --- | --- |
| Direct3D 12, 11 and 10 (64-bit games) | Apple D3DMetal 4.0b3 (`d3d12`, `d3d11`, `d3d10`, `dxgi` from the Game Porting Toolkit) |
| Direct3D 9, 8 and DirectDraw, and 32-bit Direct3D 10/11 | Wine's own wined3d |
| Vulkan | MoltenVK 1.4.2 (private Metal API build, as in 170ca) |
| OpenGL | Wine's macOS OpenGL path |

DXVK and vkd3d-proton are not included. DXVK may come later.

## What changes since 0.1120.4.6

- **Xbox One S controller over Bluetooth LE now actually remapped**
  (patch 0016). macOS reports `kIOHIDTransportKey` as
  `"Bluetooth Low Energy"` (with spaces) for the 045e:0b20 controller,
  but winebus only compared against the SDK constant
  `"BluetoothLowEnergy"`. `bus_type` stayed 0, so the patch 0015 remap,
  which requires Bluetooth, never activated, and on 0.1120.4.6 the
  right stick still acted as the triggers. The spaced string now also
  classifies as Bluetooth. Other transports are unchanged.
  Test: `tests/wine/test_iohid_ble_transport.py` (fails on the
  unpatched source, passes with 0016).
- **Not in this release: an FH302 fix.** Two source-built shims (an
  NVAPI stub, [ADR-0083](../ADR/0083-opt-in-nvapi-stub.md), and a DXGI
  driver-version front-end,
  [ADR-0084](../ADR/0084-dxgi-driver-version-front-end.md)) are built
  into `lib/calimocho/`, but an A/B on fresh prefixes showed that Forza
  Horizon 6 still shows FH302 with both. No profile installs them.

## Evidence so far (2026-10-26)

Measured on a 0.1120.4.6 clone engine with only `winebus.so` rebuilt
from the patched source (ad-hoc signed, research build, not this
release):

- Trace: the device enumerates with `bus_type 2` and the 338-byte
  remapped descriptor (it was `bus_type 0` and the native descriptor on
  0.1120.4.6).
- Paired 40 s live capture, owner pressing. macOS raw IOHID received
  1557 reports and Wine delivered 1640. The XInput state showed
  A/B/X/Y as 0x1000/0x2000/0x4000/0x8000, LT and RT independently
  0–255, and the right stick across its full RX/RY range.

Steps:

1. After the prefix is created or updated for this engine, copy ${ENGINE_ROOT}/lib/wine/x86_64-windows/d3d12_tsshim.dll to <prefix>/drive_c/windows/system32/d3d12.dll.
2. Set HB_D3D12_REAL to Z: + ${ENGINE_ROOT}/lib/wine/x86_64-windows/d3d12.dll with backslashes.
3. Keep XODUS_PRIVATE_RUNTIME_COM_STA unset (runtime COM must stay MTA).

## Known issues

- Vampire Survivors (Xbox PC build) exits with code 3 about 20 seconds
  after its window opens. Balatro (Xbox PC build) exits without a
  window. Both behave the same on the earlier Calimocho development
  engine, so the cause is the launch method, not this engine. Neither
  is supported.
- Direct3D 9 and older games use Wine's own wined3d, not D3DMetal. No
  such game was part of this release's tests.

## Replacing an LGPL library

The LGPL lets you swap the LGPL libraries for your own builds. The
GnuTLS family, FreeType and every Wine module stay separate dynamic
libraries under `lib/wine/x86_64-unix/` and `lib/wine/*-windows/`.
Build your version, give it the same install name (`@rpath/<name>`),
sign it at least ad hoc (`codesign --force --sign - <file>`), and
replace the file. The Wine loader is signed with library validation
off, so a library with a different signature loads. This was
checked by replacing `libgnutls.30.dylib` with an ad-hoc signed build:
HTTPS still worked.
