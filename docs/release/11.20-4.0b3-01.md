# Calimocho engine 11.20-4.0b3-01

> If you can afford it, buy [CrossOver](https://www.codeweavers.com/crossover).
> CodeWeavers wrote most of the macOS Wine work this engine is built on,
> and CrossOver comes with support, which this engine does not.

**Superseded by [11.20-4.0b3-02](11.20-4.0b3-02.md); never published, do not distribute.**

This is the first Calimocho engine release made for the Xode app's
beta. It is a local, signed build. It is **not published** and **not
notarized** yet; both are separate owner decisions
([ADR-0078](../ADR/0078-developer-id-signed-engine-release.md)).

The native-GS time helper (`tools/native_gs_localtime.c`) is linked into
the Wine loader as in 170ca.

The build is configured exactly like 170ca (`include/config.h` is
identical) except that FreeType is now found through `@rpath`, so the
engine needs no `DYLD_FALLBACK_LIBRARY_PATH`. PE modules are built with
`-O2` and no debug info, which makes the engine 666 MB instead of 1.8 GB.
Development files (headers, import libraries, `winegcc`, `widl`, and so
on) are not installed.

## What is left out, on purpose

- Forza Horizon 6 diagnostics: frame clock, VEH and trap probes,
  samplers, trace hooks, the thread QoS hypothesis.
- Game-specific hacks: CodeWeavers W^X and MXCSR hacks in
  `ntdll/unix/virtual.c`, the GPU identity spoof in `win32u` and
  `ntdll/loader.c`, and a d3d12 shim from an external engine. Forza needs
  them, so **Forza does not run on this engine**. Turning them into
  per-game, opt-in switches is an owner decision.
- Earlier generic candidates that still need their own review: ntdll
  threadpool I/O completion, the kernelbase fiber slot fix, NX always on
  under Rosetta, the `XODUS_MUTE_AUDIO` process mute, the winemac icon
  reply copy.
- GDK runtime fixes (PlayFab/XSTS tokens, PFX local saves). They belong
  to the Xbox GDK runtime (xgameruntime), not to the Wine engine.
- Other admitted engines Xode binds per game (AGS 5.4 + minidump for
  DiRT 5, empty GameInput for The Witcher) and the ALPC/UWP research.
- `MTL_HUD_ENABLED=1`, which the 170ca registry set. The Metal HUD is a
  diagnostic and is off by default here.

## Install

Standard location:
`~/Library/Application Support/Xode/Engines/calimocho-11.20-4.0b3-01/`.
The root holds `calimocho-engine.json`, whose paths are relative to it.

Xode should download, check and unpack the archive itself (no quarantine
attribute, so no Gatekeeper prompt). By hand:

```bash
mkdir -p "$HOME/Library/Application Support/Xode/Engines"
shasum -a 256 -c calimocho-11.20-4.0b3-01-macos.zip.sha256
ditto -x -k calimocho-11.20-4.0b3-01-macos.zip "$HOME/Library/Application Support/Xode/Engines/"
```

Until the archive is notarized, a copy downloaded with a browser carries
a quarantine attribute and macOS may refuse to run it.

## Verify

```bash
E="$HOME/Library/Application Support/Xode/Engines/calimocho-11.20-4.0b3-01"
codesign --verify --strict --verbose=2 "$E/bin/wine"
codesign -dvvv "$E/bin/wine"   # Authority=Developer ID Application: Dragos Hont (M62Z4M5EUY)
codesign --verify --strict "$E/lib/external/D3DMetal.framework"   # Apple's own signature
(cd "$E" && grep -v '^link ' MANIFEST.sha256 | shasum -a 256 -c --quiet)
```

| D3D11 present probe through D3DMetal | 120/120 presents, read-back pixel matched, result 0 |
| D3D12 present probe through D3DMetal | 120/120 presents, read-back pixel matched, result 0 |
| Vulkan present probe through MoltenVK (wide lines required) | 120/120 presents, read-back matched, result 0 |
| WinHTTP HTTPS GET with certificate validation (GnuTLS) | status 200, result 0 |

These prove the engine runs. They do not prove any game works. A game
may only claim support on this engine after a launch sweep on this exact
build.
