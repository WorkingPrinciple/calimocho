# Calimocho engine 0.1120.4.5 (calimocho-11.20-4.0b3-05)

> If you can afford it, buy [CrossOver](https://www.codeweavers.com/crossover).
> CodeWeavers wrote most of the macOS Wine work this engine is built on,
> and CrossOver comes with support, which this engine does not.

Fifth Calimocho engine build for the Xode beta. It is the first
reproducible build: two clean builds from the same commit give
byte-identical unsigned engines, Windows modules included
([ADR-0081](../ADR/0081-reproducible-engine-builds.md)). It supersedes
[0.1120.4.4](11.20-4.0b3-04.md). It is Developer ID signed with the
hardened runtime and a secure timestamp, and notarized by Apple with
Apple's D3DMetal inside
([ADR-0078](../ADR/0078-developer-id-signed-engine-release.md),
[ADR-0079](../ADR/0079-forza-opt-ins-in-the-general-engine.md),
[ADR-0080](../ADR/0080-minimal-engine-entitlements.md)).

## Version

Version **`0.1120.4.5`** (owner's scheme, 2026-10-26):
`0.<Wine major+minor>.<Apple GPTK major>.<our build number>`.

- `1120`: Wine 11.20 (`VERSION` in the Wine source).
- `4`: Apple Game Porting Toolkit 4 (D3DMetal `CFBundleShortVersionString`
  `4.0b3` in the framework's `Info.plist`).
- `5`: Calimocho build 5. Any change to a shipped file, including a new
  GPTK beta, bumps it.

The engine ID is `calimocho-11.20-4.0b3-05` so that the exact
components are readable from the folder name. `VERSION` and
`calimocho-engine.json` carry `0.1120.4.5`, and the manifest records
the source commit. Source: <https://github.com/WorkingPrinciple/calimocho>,
tag `engine-0.1120.4.5`.

## Graphics APIs

| API | Path in this engine |
|---|---|
| Direct3D 12, 11 and 10 (64-bit games) | Apple D3DMetal 4.0b3 (`d3d12`, `d3d11`, `d3d10`, `dxgi` from the Game Porting Toolkit) |
| Direct3D 9, 8 and DirectDraw, and 32-bit Direct3D 10/11 | Wine's own wined3d |

| OpenGL | Wine's macOS OpenGL path |

DXVK and vkd3d-proton are not included. DXVK may come later.

## What changed since 0.1120.4.4

- **Reproducible Windows modules.** Wine and the tsshim link their PE
  modules with `--no-insert-timestamp`, so `TimeDateStamp` is 0 and the
  `CheckSum` GNU ld computes is the same on every build. The release
  tool fails if any of our PE modules carries a link timestamp.
- **Pinned toolchain.** `versions.json` pins Xcode 27.1 (27A9275), the
  macOS 27.0 SDK (26A425), Apple clang 21.0.0 (clang-2100.3.34.2), Apple
  ld-27037.1, mingw-w64 GCC 16.2.0 with GNU ld 2.47, bison 3.8.2, flex
  2.6.4 and GNU make 3.81, each by version and SHA-256. The build stops
  on any other toolchain.
- No source patch, dependency, entitlement or environment setting
  changed. Only the PE link flag and the toolchain check are new.

## What changed in 0.1120.4.4

- `LICENSE` names FreeType 2.14.3 and its 1996-2026 credit line.

## What changed in 0.1120.4.3

- **FreeType 2.13.3 → 2.14.3** (2026-03-22 security maintenance release).
  2.14.2 fixed CVE-2026-23865 (integer overflow in variable-font
  `tt_var_load_item_variation_store`), which affects 2.13.3. Wine parses
  fonts that games ship, so this is real attack surface.
- **Minimal entitlements** ([ADR-0080](../ADR/0080-minimal-engine-entitlements.md)):
  only the Wine loader keeps one entitlement,
  `disable-library-validation`. `bin/wine` and `bin/wineserver` have none.
  JIT, unsigned executable memory, executable page protection and DYLD
  environment entitlements are gone.
- **No build or user paths in shipped files.** FreeType, GnuTLS, nettle,
  GMP, libtasn1 and the tsshim are built with `-ffile-prefix-map`, debug
  symbols are stripped (`strip -S`, exported symbols checked unchanged),
  and GnuTLS's system priority file is the standard
  `/etc/gnutls/config`. The release tool now fails the build if any
  non-Apple file contains `/Users/`, `/opt/homebrew/` or a build
  directory.
- The engine manifest records the source commit and whether the tree was
  clean.

## What changed in 0.1120.4.2

- Forza Horizon 6 opt-ins (patches 0006-0013), off unless the FH6
  profile sets their flags; the GPL-3.0 Highball tsshim as
  `d3d12_tsshim.dll`, inactive unless the profile copies it into the
  prefix; full licence texts under `licenses/`.

## Known issues

- Vampire Survivors (Xbox PC build) exits with code 3 about 20 seconds
  after its window opens. Balatro (Xbox PC build) exits without a
  window. Both behave the same on the earlier Calimocho development
  engine, so the cause is the launch method, not this engine. Neither
  is supported.
- Direct3D 9 and older games use Wine's own wined3d, not D3DMetal. No
  such game was part of this release's tests.

## Install

`~/Library/Application Support/Xode/Engines/calimocho-11.20-4.0b3-05/`,
next to older builds until Xode switches. Xode should download and unpack the
archive itself (no quarantine attribute). By hand:

```bash
mkdir -p "$HOME/Library/Application Support/Xode/Engines"
shasum -a 256 -c calimocho-11.20-4.0b3-05-macos.zip.sha256
ditto -x -k calimocho-11.20-4.0b3-05-macos.zip "$HOME/Library/Application Support/Xode/Engines/"
```

## Replacing an LGPL library

The LGPL lets you swap the LGPL libraries for your own builds. The
GnuTLS family, FreeType and every Wine module stay separate dynamic
libraries under `lib/wine/x86_64-unix/` and `lib/wine/*-windows/`.
Build your version, give it the same install name (`@rpath/<name>`),
sign it at least ad hoc (`codesign --force --sign - <file>`), and
replace the file. The Wine loader is signed with library validation
off, so a library with a different signature loads. This was
checked by replacing `libgnutls.30.dylib` with an ad-hoc signed build:
HTTPS still worked.
